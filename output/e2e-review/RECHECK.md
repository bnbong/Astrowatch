# E2E 재검증 결과

검증일: 2026-11-20 (Asia/Seoul). 실제 `requests` HTTP 호출 11건. 기존 입력과 날짜를 그대로 재사용했으며 S03→S14→S15→S16은 동일 신규 세션에서 순차 실행했다. 로그의 모델명은 `claude-haiku-5-5`다.

모든 요청은 `POST /api/chat`, JSON `{session_id, message}`, `X-Requested-With: Astrowatch` 및 대상 포트와 일치하는 `Origin`을 사용했다. S20만 `http://127.0.0.1:8003`, 나머지는 `http://127.0.0.1:8000`이다. :8004는 지정 시나리오가 없어 호출하지 않았다. 브라우저·모의 응답·패키지 설치는 사용하지 않았다.

캘린더 등록은 실행하지 않았다. S16 원문에는 계획 번호가 없고, 코드상 번호가 있어야 등록 경로로 진입함을 사전 확인했다. 실행 로그에도 `add_plan_to_calendar` 호출이 없다. 일부 관측 요청의 `get_calendar`는 읽기 조회다. 계획 저장·수정·삭제 API는 호출하지 않았다.

## 요약

**11건 중 FIXED 9건, PARTIAL 2건, NOT FIXED 0건.** R1/R2/R3/R4/R5/R7 및 S09의 지정 재현 조건은 수정 동작을 확인했다. S03/S14는 회귀가 없고, S15는 조건 갱신은 정상이나 변경 설명에 회귀가 있다. S20 AUTH 처리 자체는 유지되지만 “경고 없음” 문구는 수정이 필요하다.

S10은 정규화된 단일 밤 조건까지 확인했으며, 2030년 현상 자료 부재로 기존처럼 두 날짜 후보가 생성되는 경로 전체는 관찰하지 못했다. S03의 단일 밤 240분 추천이 보조 근거다. 11/18 입력은 이제 과거이므로 예보 결과는 원본과 직접 비교하지 않았다. S13의 상한 표시는 HTTP 필드·본문 기준으로 검증했으며 UI 배너는 검증하지 않았다. R8 Markdown 렌더링도 브라우저 금지 범위에 따라 이번 검증 대상에서 제외했다.

추가 문구 관찰: S13 본문은 “다른 날짜나 지역을 찾아도 의미가 없다”고 한 뒤 남쪽 저위도 관측을 권한다. 지정된 stop_reason/상한 결함은 해소됐지만 이 지역 일반화 문구는 다듬을 여지가 있다.
