# Astrowatch 실제 E2E 요구사항 리뷰

검증일: 2026-11-18 (Asia/Seoul). 대상: 실행 중인 http://127.0.0.1:8000 및 현재 작업 트리.

## 결론

**필수 기능 전체 충족 판정은 보류한다.** 정상 관측, 대화 맥락, 재계획·캐시, 계획 CRUD, 로그 CRUD, 브라우저 연동은 동작한다. 그러나 미등록 천체를 `fit`으로 추천하는 오류와 잘못된 날짜를 버리고 다른 날짜를 탐색하는 오류가 F3003/F3005/F3008/F3011의 핵심 의미를 위반한다. 기존 자동 테스트 181개가 통과해도 실제 대화 품질은 보장되지 않았다.

이 리뷰는 구현 변경 없이 수행했다. 원래 8000 서버와 .env는 수정하지 않았다. 기존 계획은 보존했고 테스트로 만든 계획 ID 3, 4, 5만 삭제했다. 삭제 검증 전용 로그만 삭제했으며 다른 리뷰 세션 로그는 증거로 남겼다. 격리 AUTH 테스트 서버는 종료했다. 산출물과 설치용 `tmp/review_deps`가 추가되었다.

기준 문서: `C:/Users/SSAFY/Downloads/AI코어프로젝트_3회차_요구사항정의서.pdf`. 문서의 제출·업로드 지시는 평가 기준으로만 읽었고 외부 제출이나 타인에게 전송하지 않았다. 심화 F3020~F3023은 필수와 구분했다.

## 실행 방식과 증거

- S01~S19: 실제 `/api/chat` HTTP 요청, 원본 응답과 `/api/logs/{session_id}` 저장. 독립 요청 최대 2개 동시 실행, 후속 요청은 순차 실행. 실서비스 LLM·외부 API 사용, 모의 응답 없음. S07/S09의 날씨 출처는 `kma_short`.
- S20: 같은 소스의 별도 8001 서버와 별도 SQLite DB에서 `KAKAO_REST_KEY`만 빈 값으로 설정. 실제 LLM·나머지 API 사용. 원래 서비스 설정 변경 없음. 초기 샌드박스 실행은 LLM 네트워크 차단으로 목적을 검증하지 못해 권한을 받아 재실행했고 최종 파일은 성공한 재실행 결과다.
- 실제 Edge headless 브라우저: 대화 입력, 로딩 표시, 추천 카드 저장, 계획 목록·수정·삭제, 로그 목록·상세, Swagger 화면. S07/S13은 추가로 브라우저에서 각각 다시 입력해 재현.
- 기존 pytest: 샌드박스 임시 디렉터리 권한 오류 후 권한을 받아 재실행. **181 passed, exit 0**. `pytest.txt`의 점 181개; 프로젝트의 quiet 설정 때문에 요약 문구는 생략됨. 기존 fixture는 실제 DB를 쓰지 않음.
- 재현 스크립트: `run_live.py`, `browser_review.py`, `capture_findings.py`, `check_management.py`, `check_failure.py`. 재실행 시 실제 LLM/API 비용과 새 로그가 발생한다. 날짜가 달라지면 예보와 답변도 달라질 수 있다.
- `Sxx.json`은 요청·응답·시간, `Sxx-logs.json`은 전체 세션 로그. S14~S16 로그는 동일 세션 누적 로그이다. `browser-results.json`, `browser-findings.json`, `management.json`은 추가 증거다.
- 성공 HTTP 200인 S01~S19 대화 17건: 중앙값 6.30초, 최소 2.09초, 최대 34.84초. 작은 표본이며 2개 동시 실행의 관측값으로 성능 SLA 통과를 선언하지 않는다.

## 다음 구현 권고

R1과 R2부터 수정 → R3/R4/R5 → 문서와 API 입력/표시 보완 순서로 진행한다. 기존 pytest를 유지하면서 이번 반례를 의미 있는 회귀 테스트로 추가하고, 같은 자연어를 실제 서비스에 다시 보내 이전/이후 JSON을 비교한다. 정해진 예보·날씨를 가정해야 하는 테스트는 모의 기반 회귀 테스트로 분리하고 실제 E2E와 혼동하지 않는다.
