**Spec-compliance notes**

- **F3022 core flow is implemented:** KNOWLEDGE plans select `search_space_docs` (`nodes.py:584–588`); retrieval uses Chroma plus name/lexical ranking (`rag/search.py:135–174`). The supplied `samples/run_knowledge.json:11–14` records KNOWLEDGE intent and an answer with source attribution. This is recorded evidence, not a newly verified run.
- **Defined failure responses exist:** `NO_INDEX`, `INDEX_MISMATCH`, and `NO_RESULT` use deterministic templates (`nodes.py:1548–1554`; `prompts.py:160–166`). Both index errors are nonfatal and nonretriable (`tools/base.py:45–55`), consistent with handling them as index preparation issues rather than authentication failures.
- **Normal Tool invocation does not propagate ordinary exceptions:** the decorator returns a `ToolSpec`, whose `invoke()` catches validation and handler exceptions (`tools/registry.py:31–44`; `tools/base.py:126–138`). Missing catch-all handling inside `space_docs.py` therefore does **not** by itself crash the graph.
- **Chroma import failure maps correctly to `NO_INDEX`:** `store.py:146–151` converts import exceptions to `IndexMissingError`, handled at `space_docs.py:52–54`. R7 concerns constructor failures after import.
- **Frontend rendering is appropriately escaped:** answers pass through `Markdown.render` (`frontend/js/chat.js:339`), which escapes HTML first and does not create links or images (`frontend/js/markdown.js:9–15`, `:34–35`). No executable-HTML injection was identified in this path. This protection is separate from LLM prompt injection.
- **Request/result limits are useful:** query length ≤300 and `k≤8` (`contracts.py:236–240`); snippets ≤400 characters (`search.py:124–132`).
- **The local threshold 0.75 is plausible but unvalidated.** It applies to cosine **plus lexical bonus**, and name matches bypass it entirely (`search.py:165–173`). The comment’s two examples are insufficient calibration. Existing tests use a fake provider and force `MIN_SCORE=99`, so they do not validate local precision/recall (`tests/test_tools_space_docs.py:18–35`, `:152–157`).
- The checked-in collection contains **321 documents, 608,432 bytes**, with maximum text length **5,996 characters**, and declares **CC BY-SA 4.0**. It meets the default size target today; R5/R6 concern enforcement on future collections.
- The scripts rebuild an index from collected documents. Code comments identify the implementation as ported from the previous project, but code inspection alone cannot establish whether this satisfies a literal requirement to reuse that project’s existing vector DB.

**Test-gap suggestions**

1. Add malicious-snippet and unsupported-answer tests. Verify that fabricated model facts and instructions embedded in retrieved text cannot become authoritative answers.
2. Test citation output containing one valid URL plus fabricated URLs, URL-prefix matches, omitted license attribution, and partial source lists.
3. Parameterize routing across the exact supplied examples, mixed knowledge/observation requests, `"관측 가능해?"`, and deliberately incorrect LLM intent outputs.
4. Simulate Chroma import failure, embedding-constructor failure, corrupt metadata, and database exceptions. Assert both nonthrowing Tool behavior and the intended response code.
5. Test output-path rejection, including repository paths outside `data/`, external paths, and symlink/junction escapes. Test actual UTF-8 serialized size with tiny budgets and oversized metadata.
6. Use a fake HTTP client to test oversized responses/cache entries without network access.
7. Add an offline local-score evaluation set with known positives, unrelated Korean negatives, and misleading name matches. Store precomputed scores/vectors so CI needs neither model downloads nor keys.
8. Test rebuild failure between active-collection deletion and staging rename (`store.py:239–241`); the current replacement sequence can lose the working index if promotion fails.
